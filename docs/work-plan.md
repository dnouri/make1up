## Framing

Build an original Three.js makeup challenge game for the browser. Public FACECARD references guide the interaction rubric. They do not supply proprietary code, branding, or assets.

The first run has six units. Research public references. Compare two architecture sketches. Build the verification tools and state model. Build the 3D makeup studio. Complete a solo challenge, judging, and share loop. Test and improve the real browser product.

The exit predicate is a production build that passes automated behavior tests and browser checks for a complete challenge, visible makeup edits, undo, reset, saved looks, judging, export, keyboard input, narrow screens, and no blocking browser errors. Screenshots must show a nonblank 3D face with distinct editable makeup. Reference coverage and remaining gaps must be explicit. This predicate does not prove market leadership or virality.

The empty project has no prior app baseline. The baseline is an absent product. Comparative reference scores use only observed public evidence. Performance uses absolute budgets and reports the machine and method.

Local changes proceed without another approval. No paid generation, uploads of private photos, deployment, Roblox access-control bypass, or multiplayer service is authorized by default. The operator can request a paid asset pipeline or online multiplayer instead of the local-only default.

Pi supports foreground parallel waves. It does not provide an event-driven background coordinator. This run uses explicit research, build, and verification waves in this session.
