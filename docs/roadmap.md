# Extend the verified studio

The solo game now has the v2 portrait, full-face tools, and a visible customization workspace. The remaining work includes device checks, human use, further art review, and creative or social additions. Planned capabilities are not released behavior.

## Validate the current loop with people and devices

- [ ] Have two first-time players select a tool, paint, undo, reframe, and finish without spoken help. Record whether each completes the task within two minutes.
- [ ] Test a physical lower-end Android phone and an iPhone. Record load, brush response, rotation, thermal behavior, memory, and export.
- [ ] Check Safari, Firefox, and a person's screen-reader workflow. Add human keyboard checks to the automated focus and native-radio coverage.
- [ ] Repair the normal makeup layout at 320 by 568. The customization workspace fits, but the existing editing stage overlaps a fixed correction dock.
- [ ] Repeat readiness and interaction measurements on a quiet machine with hardware graphics. Preserve software-renderer results as a separate dataset.
- [ ] Use the existing visual rubric to record failures. Fix the worst proven issue before adding content.

## Review and extend the v2 portrait

- [x] Make v2 the only playable portrait and look format. Start a fresh v2 lookbook without importing older storage, as the operator requested.
- [x] Add bounded face, nose, mouth, and eye-shape morphs on the locked topology. Check all 54 shape combinations and fit the lashes to the round-eye target.
- [x] Add five complexion maps with matching bust maps, four hair colors, and three iris colors. The skin and hair maps are offline source recolors, not newly photographed skins.
- [x] Add a separate crown bun and fabric band alongside the ponytail component set.
- [x] Add the same-canvas **Customize portrait** workspace with undoable choices and makeup camera restoration. Check five viewport sizes and retain the visible portrait while controls scroll.
- [x] Allow every tool across paintable face skin except lipstick, which retains its lip mask.
- [ ] Have an artist review the shapes, lash fit, color extremes, natural lip contrast, neck seam, and both hairstyles under browser lighting. Automated geometry checks are not exhaustive self-intersection or art approval.
- [ ] Add independently authored skin textures and undertones beyond the current Rain recolors. Keep their source, terms, and review evidence explicit.
- [ ] Add removable lash styles, adjustable brows, and more fitted hair silhouettes. Verify all supported view angles.
- [ ] Compare an optional AI texture draft with the authored baseline on the same head. Include seam repair, cleanup time, terms, and browser appearance in the result.
- [ ] Keep AI generation offline unless a backend with consent, spending limits, moderation, retention, and deletion rules is explicitly approved.

The [face research](research/face-pipeline.md) identifies Meshy's original-UV retexturing as one hosted trial and TRELLIS.2 as a local GPU trial. No comparative generated-face test or universal model winner was established. The checked Hunyuan3D licenses have geographic restrictions relevant to this project. Recheck exact model and service terms before use.

## Add creative depth and replay

- [ ] Have first-time players compare the current full-face painting with guided apply. Check whether tool placement and recovery are clear.
- [ ] Prototype layers and a stabilizer against the inspected reference controls. Keep them only if novice and precise editing tasks improve.
- [ ] Author more briefs with distinct visual requirements and inspect completed examples. Do not use random scores to simulate a competition.
- [ ] Test a daily brief and local collection progression. Measure completed rounds and voluntary replay with consent rather than claim retention from the presence of buttons.
- [ ] Test the actual remix flow between people on an approved deployed origin. Measure successful opens, edits, and exports. A working link alone does not prove viral growth.

## Design real social play separately

- [ ] Choose the intended audience, device floor, session size, hosting budget, and moderation owner.
- [ ] Design authoritative round state, reconnect behavior, submission limits, ties, missing votes, duplicate votes, and self-vote rules.
- [ ] Test two independent clients before showing an online-player claim. Then test reconnects, a failed submission, and abuse cases.
- [ ] Add public content only with clear reporting, moderation, privacy, and deletion behavior.
- [ ] Obtain operator approval before publishing or deploying new social services or using a paid service.

Do not rebuild a 3D lobby before these editing and social tests show that it helps the player. Public Facecard videos support its creation, reveal, and voting loop. They do not provide permission to copy its proprietary source, meshes, artwork, or branding.
